# 公开星球：使用、身份与部署设计

状态：AC-01 至 AC-09 的主链路 Design Ready；下文删除方案保留实现前的设计推导，**删除代码与页面现已部署但公开开关仍关闭**，不能把章节中的「待实现」当成当前代码状态，也不能按「Design Ready」直接开放。AC-10/AC-11 的保留期、运营主体、用户权利渠道及服务适用性尚未闭合。当前运行与验收事实以[公网交付记录](../plans/2026-09-24-public-launch.plan.md)的最新检查点为准。目标是交付可分享的线上产品，而不是把 localhost 原型直接加一个代理。

## 新访客实际怎么用

一个从未听说 Bibo Planet 的人打开 `planet.bibo.bot`：首屏看到一颗星球、三只性格不同的精灵，理解「同一只精灵会遇见所有人，没有主人」。无需注册即可浏览精灵、能量和匿名化的星球近况。要说话时进入注册面板，取一个昵称、设密码，立即回到刚才选择的精灵；第一次发送能看到明确的等待状态和真实回复，继续追问可以延续自己的对话。退出后再登录，自己与各精灵的对话仍在。另一人注册后面对的是同一只精灵，它可引用此前的公开可共享经历，但不能打开前一人的原始对话记录。错误、能量不足、每日额度耗尽都有可理解的反馈和恢复路径。

## 真实候选与选择

| 路径 | 价值 | 代价/风险 | 结论 |
| --- | --- | --- | --- |
| 国内 ECS 上放完整 Node/Harness，Cloudflare 提供独立 HTTPS 入口 | 复用现有实例与 `@nextclaw/harness`，本机 DeepSeek 在国内可调用，持久磁盘现成 | 与现有服务同机；需隔离用户/目录、反代保护、备份、限流 | 采用，先小流量公开 |
| 全部放 Cloudflare Worker/D1，直接调模型 | 部署快、边缘扩缩容好 | Node Harness 与文件化精灵工作区难移植，会偏离 NextClaw 复用；存储模型需重写 | 不采用 |
| 境外节点运行完整 Harness，使用 `codex-sub` 订阅代理 | 模型能力强 | 个人订阅不适合作公开访客的生产 API；境外实例与持久存储待购置，且成本、可靠性未知 | 不采用；`codex-sub` 仅内部验证 |

`bibo.bot` 根域现在是另一产品站点，不覆盖它；使用 `planet.bibo.bot`。Cloudflare Worker 是独立 HTTPS 静态站与受控 API 代理，后端 Node 仅监听 loopback，由 ECS 现有 HTTPS Nginx 的独立路径代理，并要求仅 Worker 持有的随机认证头。Worker 与 ECS 间保持 HTTPS，不把模型密钥放在 Worker 或前端。Worker 自定义域名自动创建 DNS/证书；若该配置不可行，先用独立 `workers.dev` URL 验证但不把临时地址当最终品牌链接。Cloudflare 官方参考：https://developers.cloudflare.com/workers/configuration/routing/custom-domains/ 。

## 状态 owner 与运行边界

- `AuthStore` 拥有账号、密码哈希、会话 token 哈希、注册/登录/退出与每日账号额度。访客身份不再依赖可自填的 UUID cookie；cookie 为随机不可猜 token，`HttpOnly; Secure; SameSite=Lax`。所有修改原子落盘，进程单实例运行，服务升级前备份。
- `WorldStore` 继续拥有精灵能量、共享遭遇与各账号的私人对话。能量与对话只在模型成功后一起写入；同一精灵串行。公开世界接口只给必要的匿名化统计和有限事件摘录，不给其他用户的会话原文。
- `SpiritRuntime` 用 `@nextclaw/harness` 提供的模型注册/路由能力调用真实模型；传入精灵身份、该账号最近对话、共享遭遇与安全边界。**公开版不向模型提供文件、命令、网络工具**。现有完整 Agent `runTask` 在本地原型可用，但其工具拥有宿主能力，不能拿 `restrictToWorkspace` 冒充安全沙箱。精灵自主改造工作区与 mini-app 延后到真正有执行隔离之后，不能伪称已经开放。此取舍保留 NextClaw SDK 依赖与模型能力，但公开版暂不使用完整有工具的 Agent session，须对用户如实说明。
- API 服务拥有请求验证、来源检查、客户端/IP 速率限制和返回码。部署边界上，Node 进程使用非 root 专用账号、只读应用目录、单独可写数据目录、systemd 限权；Nginx 只暴露指定路径且校验内部认证头。公开可观察的敏感日志不记消息正文和密钥。

### 过期会话哈希的启动清理

现状是会话有效期 30 天，`AuthStore.account()` 已拒绝到期 token，但哈希仍留在 `accounts.json`，累积增加文件和残留身份元数据。只在登录时清理会遗漏长期不登录的世界；另起定时任务会增加运行 owner。选择在每次 `AuthStore.initialize()` 读取已有状态后、服务监听前过滤 `expiresAt <= now` 的会话，并仅在确有过期项时原子写回。现存有效会话、账号、额度和世界文件不变；写回失败时拒绝启动，不以空状态覆盖原数据。这里仅清理**活动账号文件中的过期会话哈希**，并不删除账号、私人对话、共同遭遇或历史备份，也不承诺到期瞬间完成物理清除。备份定时服务会使进程至少按日重启；如运行方式改变，须重新审查清理频率。

验收先在隔离状态里放入同一账号的过期与有效会话，重启后确认前者从磁盘和查询中消失、后者仍可用；再做 TypeScript、全量测试和 diff Review。生产发布前取专用备份，远端只重启 Bibo 服务，复查原有会话、公网世界与旧站。当天新创建的生产会话自然尚未到期，不能凭一次生产重启声称已观察到线上真实过期记录被删除。

### 持续运行中的会话数量与无效退出

后续可靠性审查发现，启动清理只解决重启时的旧哈希；服务持续运行时，每次成功登录仍追加一条会话，而带伪造格式正确 Cookie 的退出请求即使找不到会话，也会重写整个账号文件。单 IP / 全站登录限速只限制增长速度，不能限制一个账号的有效会话总数或无效退出造成的写放大。这是 `AuthStore` 内的局部生命周期合同缺口，不改变世界、模型或 Cookie 协议。

真实旅人可在手机和电脑分别登录并继续自己的会话；同一账号产生第九个有效登录时，最早到期的旧会话失效，原设备下一次访问需重新登录，其他账号和自己的对话不受影响。8 个有效会话覆盖现有生产聚合观测的最大 3 个，限制反复登录造成的长期增长；用户若有更多设备需求再根据实际数据调整。服务升级时不批量注销仍有效的旧会话；上限只在该账号下一次成功登录时裁剪。现有 30 天到期规则保持不变。

候选①只保留启动清理，无法约束长期运行；②每次成功注册/登录时清理全站到期会话，并把该账号旧有效会话保留至多 7 个后签发新会话，且无效退出直接无写返回；③迁移事务数据库或另建清理定时任务，能解决更大规模问题但会改写备份/恢复链路或增加第二个生命周期 owner。采用②，`AuthStore` 仍是唯一 owner：先在原有串行队列中计算下一份会话集合，再与账号变更一起原子落盘，落盘失败则不更新内存也不发出新 Cookie；错误密码、超速与无效退出不写状态。裁剪按 `expiresAt` 从晚到早保留，确保本次新登录留在集合中。该边界不承诺限制账号或世界状态文件的全部长期增长，也不替代备份保留期。

验收：同一账号持有 8 个未过期会话（包含注册时签发的首个会话）时都仍有效；签发第 9 个时仅最早一条失效，新会话和另一账号的会话有效；到期哈希在不重启服务的成功登录/注册时从磁盘移除；伪造或重复退出不改动账号文件且响应仍不泄露会话是否存在；正常退出只移除自己的会话；用旧版账号文件启动与公网现有账号继续登录均不丢数据。发布前先核对生产每账号活跃会话聚合数与专用备份，发布后通过真实公网账号的登录/退出/会话恢复验证正常路径；不在生产制造九次登录来测试淘汰边界。

## 共享世界的可见信号

首屏不能只靠文案声称“同一批精灵属于所有访客”。`WorldStore` 从既有精灵遭遇记录派生每只精灵最近一次相遇时间，公开世界接口只返回时间，不返回访客身份或消息。前端在精灵卡片上用相对时间提示最近有人来过，页面可见期间低频刷新；发送成功时立即更新本地提示。匿名访客也能看到世界确实在变化。失败的刷新不清空已有世界，也不伪造活动。

不公开原始对话摘录：那会让“私人对话列表隔离”失去意义；不在首版另开模型调用生成公开日报：它增加成本、审核和一条新的事实 owner。未来若确有需求，再单独设计“可公开的共同事件”及其授权边界。

这里的「列表隔离」不能误读为共同遭遇的内容保密：当前 `SpiritRuntime` 会把近期共同遭遇中的旅人原始输入和精灵回复作为模型记忆传入另一位旅人的对话。系统提示要求不要逐字泄露，但模型提示不是确定性的访问控制。2026-09-24 用两个受控公网身份试问前一人的原句，真实模型两次拒绝逐字复述、只转述线索；这只是观察，不是安全保证。正式告知必须明确「不要留下秘密、你的话可能通过精灵影响别人」，并将账号导出/删除范围与可能已经生成给别人的衍生内容区分。若产品将来要承诺严格的私人原文保密，就必须改变送入共享模型上下文的数据合同，而不是只修改提示词。

当前先把页首与注册/登录弹窗的含蓄提醒统一为「发送成功的内容会成为精灵的共同记忆；其他旅人可能从它的回应中得知。请勿输入隐私或秘密。」并提高提示文字可读性。这是产品层的事实告知，不是隐私协议、同意记录或模型输出的保密保证；运营主体、处理期限和权利路径仍按 AC-10 独立闭合。

### 极窄手机上的同一信号

320px 宽的真实浏览器视口中，三张卡片仍须同时可见，且标题「不属于任何人」不拆成孤立的第三行。可选方案有三卡纵向堆叠、横向滑动和缩写活动时间；前两者分别推远对话区或隐藏一只精灵，首版采用第三种。桌面保留完整的「几分钟前有人来过」，手机卡片用「几分钟前／几小时前／刚刚／等待相遇」，语义不变、来源仍是同一时间戳；移动卡片靠卡片轮廓与选中态传达可点击，隐藏会与短标签争位的装饰箭头；极窄视口缩小标题字号并收起页脚次要英文。验收覆盖 320px 与 390px，检查三卡、标题、输入框和横向溢出，而不是只测 CSS 断点是否命中。

后续用**初始视口而非整页截图**复查，320×700 发现卡片从约 620px 开始，到 735px 才结束；新访客首屏只能看见卡片顶部，连精灵名字都不全。候选是把卡片移到星球图之前、加一个跳转按钮，或在短手机视口收紧星球舞台：前者改变“先看世界再遇见精灵”的叙事，额外按钮仍不能展示三只不同的精灵；选第三种。高度不超过 760px 的手机缩短舞台和星球本体，高度不超过 680px 时再适度压缩顶部留白；保持标题、告知、星球和三卡的顺序，不缩小隐私告知字号。预览中 320×700 卡片底部约 690px、375×667 底部约 658px，三只名字和活动提示都在首屏。正式验收须用已发布的 CSS 在两个初始视口复核几何与截图，并确认 390×844 和桌面未退化、无横向溢出；点击精灵仍应把访客带到对话区。预览不算已发布证据。

## 旧遭遇的按线索找回

第二轮可靠性审查发现：`WorldStore` 虽永久保存共同遭遇，`SpiritRuntime` 只读取最近 10 次；第 11 次之后，另一个访客留下的旧线索实际上不会再进入精灵上下文。`workspace/agents/*/MEMORY.md` 当前未进入模型上下文，也不能把空占位文件算作长期记忆。这个缺口属于现有世界状态与模型消费者之间的局部合同，不要求新增记忆 owner 或更改公开 API。

真实用户链路：旅人 A 向墨里讲一个非私密线索 → 其他旅人陆续发生超过 10 次相遇 → 旅人 B 用同一话题线索向墨里提问 → 墨里仍可接触 A 的旧遭遇并自然回应；B 的私人会话接口依旧只有 B 自己的原始消息。旧线索找回不改变访客注册、页面或能量规则，也不额外消耗模型调用。

候选：①继续只带最近 10 次，简单但直接违背“同一个存在持续记得共同经历”；②每隔若干次让模型自写摘要，能做主题归纳，但多一条推理账单、摘要失真和需要备份/恢复的新事实；③从既有遭遇中按当前消息的话题词找回少量旧记录，与最近记录共同组成有界上下文。当前选择③：仍以 `WorldStore` 的遭遇为唯一事实源，检索只是读取时投影，兼容已有数据，失败退化为最近记录。它是**有线索的回忆**，不是完整自主长期记忆；不能把“能找回旧话题”宣传成“永远记得所有事”。后续若要真正自写记忆，需另行证明预算、抗注入、状态 owner 与备份合同。

实现边界：最近 10 次始终保留；仅在更早记录中按**至少四个连续汉字的重合线索**或**至少三个字母/数字组成的完整词**选择至多 4 条，按匹配强度排序，限制每条进入提示词的长度。查询中的“你还记得”“还记得吗”等泛化套话不算主题线索；无足够线索时不随机塞入旧私聊。两三字名称、同义改写和不含线索的开放回忆不保证命中，这个限制需如实对待。旧记录仅传给同一精灵的模型，不进入匿名世界 API；提示词继续明确这是访客经历而非高优先级指令。无匹配、旧状态或模型失败沿现有链路处理，不新增写入与迁移。

验收：先用超过 10 次遭遇的隔离状态验证目标旧线索被选中、无关旧消息不入上下文、最近记录仍保留；再用真实模型对隔离状态的跨访客追问确认能据旧线索回应，并在更新后复查公网正常对话、账户隔离和资源计量。静态/隔离测试只证明机制，不替代真实浏览器与完整获客验收。

## 资源与滥用边界

每次消息最多 1500 字符，模型输出有 token 上限和超时；每账号每天有低额度，单 IP 对注册与登录限速，模型调用并发数有限，全站每日调用上限有限。前端显示真实能量，额外运营预算不伪装成精灵能量。任何模型失败不计为成功对话，但在调用模型前持久预留一次尝试，防止失败、超时或重启后无限重试；初期每账号每日最多 12 次成功、18 次尝试，全星球最多 240 次尝试。供应商余额不足时全站明确告知，不切换模拟回复。调用次数不是账单金额硬上限，仍需监控供应商内部重试、价格和余额；初始阈值可按真实单轮 token 与费用再校准，不能伪装成精灵经济体系的永久规则。

公开链路复核又发现账号层资源边界：原来只有单 IP 注册/登录限速，成功注册没有全站持久上限；IP 尝试 Map 也不删除过期键。单台 ECS 的账号 JSON 和进程内存可能被大量分散来源持续放大。候选是只靠 Cloudflare 挑战（需要额外外部配置并增加首次使用摩擦）、只清理 Map（解决内存但不限制账号文件）、或在现有 `AuthStore` 单一 owner 内补**持久的每日成功注册上限 + 有界尝试表**；首版采用第三种，保留日后按实际滥用情况增加边缘挑战的空间。当天最多成功注册 240 个账号，与全站每日唤醒尝试数量同量级；计数随状态原子落盘，删除账号不返还名额；旧状态以仍存在的当日账号创建时间建立下界，已删账号无法追溯。注册先在串行队列内检查额度与昵称，再计算密码哈希，避免额度耗尽或重名请求仍执行昂贵哈希。注册与登录分别增加全站每 10 分钟 1200 次和 600 次尝试的进程内保护；每 IP 既有限额保留。IP 尝试表最多跟踪 10,000 个键，满时先清过期项，再按最久未使用键逐出，保护内存但**不能**声称这可以抵御大型分布式攻击或成为永久的身份系统。注册上限可能在遭攻击时被耗尽并暂时拒绝真实新用户；页面必须显示可理解的 429，运营者需要观察并调整，而不能把安全阈值伪装成剧情规则。

验收：旧状态无计数字段可继续注册且不会低估当日已有账号；当天达到 240 后重启仍返回 429、账号文件不增长；并发第 240/241 个由同一串行队列裁决；重名及额度耗尽路径不做 scrypt；大量不同 IP 登录失败后尝试表大小有界；原有账号登录、正常注册、对话和删除/额度结转不回归。真实公网只做不耗尽上限的烟测和错误链路检查，不在生产制造 240 个账号。

## AI 身份提示与未决的公开服务要求

2026-09-24 复核发现：产品文案和网页摘要称“AI 精灵”，但实际对话区及每条回复没有明确可见的 AI 身份提示；访客沉浸在星球故事里时可能误解回复来源。对照[《人工智能生成合成内容标识办法》](https://www.cac.gov.cn/2025-03/14/c_1743654684782215.htm)与[《人工智能拟人化互动服务管理暂行办法》](https://www.cac.gov.cn/2026-04/10/c_1777558395078289.htm)，先补可验证的界面事实，不据此宣称完成全部合规要求。

真实路径是：新访客选精灵时，在聊天区域看到“AI 精灵 · 回复由模型生成”的清晰提示；登录后每条已完成的精灵回复署名旁也显示“AI 生成”，等待状态不提前标记为已经生成。如此即使已滚过首屏、重登读历史或只看一条回复，也能认出对象不是自然人。只在首页写一次说明无法覆盖持续对话；仅每条回复标注则新访客在发送前仍不知道。两个位置共用固定文案，不改变模型回复正文，也不引入新的状态 owner 或 API。验收用桌面和 320/390px 手机真实浏览器检查提示可见、无挤压，并确认历史与新回复都带来源标记。

此局部修复**不**解决运营主体、备案/登记、年龄保护、投诉处理或用户数据复制/删除。它们以[公网验收 AC-10/AC-11](../plans/2026-09-24-public-launch.plan.md)单独追踪；不能把视觉提示当成正式开放的完整法律判断。

模型名称与备案号的公示是另一层：前端写死名称最省事，却会在后端更换模型时悄悄变成错误陈述；另建产品详情页能容纳更多信息，但增加首版页面与发现路径。当前选择由实际运行的 `SpiritRuntime` 向 `/api/world` 提供模型信息，对话区域的标题旁始终显示当前模型名称，并仅对核验过的 `deepseek/deepseek-chat` 显示 DeepSeek 官方[模型公示](https://cdn.deepseek.com/policies/zh-CN/model-algorithm-disclosure.html)中的 `Deepseek Chat / Beijing-DeepseekChat-202404280016` 与原始来源链接；切换到未核验模型时不继续宣称旧备案号。国家网信办[已备案信息公告](https://www.cac.gov.cn/2024-04/02/c_1713729983803145.htm)要求已上线应用在显著位置或产品详情页注明所用已备案模型名称与备案号。这只是基于当前配置的模型来源披露，不把模型服务自身的备案号冒充 Bibo 应用备案，也不完成 AC-10/AC-11 的其他义务。验收要看真实生产配置、接口字段、桌面和 320px 对话区渲染，以及换模型时不误显示旧号。

## 旅人自行复制数据（分步落实数据权利）

以下先记录「导出对话」的历史首步及当时的取舍；当前目标是下方的单一「导出我的数据」，成功发布后以新接口为现行合同，旧的三端点前端拼装不再使用。

用户任务：已登录旅人从页首按「导出对话」，浏览器下载一份包含本人和三只精灵全部原始对话的 JSON；未登录者看不到入口；断网或其中一份会话读取失败时明确报错，不下载残缺文件。文件由浏览器即时生成，不上传到其它服务或持久存入浏览器；按钮忙态防止重复下载。移动端保持按钮可达，不挤压品牌或退出入口。

比较三条真实路径：①让用户手工逐只复制屏幕上的消息，操作难、格式丢失；②新增服务端导出 API，一次返回全量，但会扩大敏感数据查询面并给现有后端增加合同；③客户端并行调用既有 `GET /api/spirits/:id/conversation` 三个账号保护端点，全部成功后组装文件。当前固定三只精灵、原有服务端已按会话身份隔离，因此选③；不增加按任意访客 ID 检索的入口，世界列表只提供精灵 ID/名称。未来精灵数量很大或需要包含账号/后台资料时再评估②，不把当前的「对话导出」误称为「导出所有个人信息」。

导出只包含当前会话对应账号 ID/昵称、生成时间和每只精灵与该旅人的消息；不包括其他旅人的原文、密码/会话哈希或共同遭遇的跨访客上下文。通过现有页面按钮触发下载，在页面中给出加载和失败反馈。验收：两个隔离账号各自导出后只读到自己的对话；匿名没有入口；任意一份数据读取失败时无文件；桌面及 320px 手机按钮可操作。此功能只完成交互数据复制的一部分，账号删除、共享遭遇删除、备份保留期和申请渠道仍属于 AC-10/AC-11 待办。

### 从对话复制扩为本人在线数据导出

用户从已登录页面按「导出我的数据」，浏览器下载一份 JSON：账号 ID、昵称、创建时间和当日使用计数；三只精灵各自与本人的私人会话，以及本人写入共同遭遇的原始输入、精灵回复、时间和模型消耗。下载前提示文件可能包含敏感内容，需要自行妥善保存。匿名者没有入口，旧 cookie、恶意查询参数或其他账号不能导出别人的记录。文件只在浏览器即时生成，不上传第三方。

比较：继续在前端分别读三份私人会话，再加账号/共同遭遇端点，会出现多次请求、部分失败和多个数据范围解释；保留两种并列的「导出对话」「导出数据」会让访客难判断哪份完整。选择把既有按钮升级为**单一**完整导出：服务端 `GET /api/account/data` 只从已验证的会话取得账号 ID，分别调用 `AuthStore` 与 `WorldStore` 各自的本人数据只读投影，组装一个有版本号的响应；客户端仍只负责生成本地下载。没有按用户指定 ID 查询的管理接口，也不开放其他人的原始共同遭遇。服务端读取期间若别的对话刚好完成，各字段可能代表略有不同的读取时刻，因此只标注导出生成时间，不宣称跨文件原子快照；不为这个低频读操作暂停全部精灵。失败时整个下载不产生残缺文件。

密码哈希、会话 token 哈希、限流内存、模型凭据和其他旅人的原文不进入下载；加密备份是在线数据的历史快照，不另作为一份副本塞进 JSON。其他旅人此前收到、可能间接受本人的输入影响的生成回复目前无法可靠归属，也不宣称这个按钮能导出或清除它们；有关争议仍需可用的权利申请路径。验收除两个真实登录身份分别下载并互查外，还要组装 HTTP 边界测试匿名 401、伪造 `accountId` 不改变导出目标、返回不含密码/会话哈希，及三只精灵共同遭遇按 `visitorId` 精确筛选。此阶段只增强复制能力，不把 AC-10/AC-11 其余要求改为可选。

删除不能简单等同于从 `conversations[accountId]` 移走一份列表：同一旅人的文字也出现在各精灵的 `encounters` 中，可能已被精灵转述进其他旅人的私人回复；加密的本地与 OSS 历史备份仍会保留旧快照。候选①保留“去身份”的共同遭遇，成本低却无法保证自由文本已去识别；候选②把该旅人的原始会话与其贡献的共同遭遇都从活动世界移除，再删除账号/会话，真实符合用户直觉但需要跨文件幂等恢复，且仍不能自动清除其他人此前收到的衍生回复。后续倾向②，并另设人工权利申请路径处理衍生内容争议；在备份到期/恢复防回流与运营渠道落实前，不上线一个声称“全部永久删除”的误导性按钮。账号删除应要求再次验证密码、明确确认影响，并在模型生成进行中拒绝或等待，不能让并发消息在删除后重新写入。上述是待实现设计，不是当前已交付能力。

### 账号删除的可执行边界（待实现，不等于全部数据即时消失）

旅人从本人已登录页面进入「账号与数据」，先可导出对话，再明确看到将删除哪些在线数据、共同世界会失去哪些相遇、加密备份可能在保留期内仍存在，以及其他旅人此前收到的衍生回复无法自动收回。只有重新输入密码并确认后才发起删除；请求进行中禁止重复操作。成功响应后本人所有会话失效、无法再登录，同名昵称可重新注册但得到新的身份和空白历史。失败不能显示「已经全部删除」，而要给出可追踪的处理中或失败状态与后续处理路径。

主链路选择候选②，不把自由文本简单去标识后留在世界中，也不为首版迁移成全新数据库。服务端先禁止该账号再发起模型调用，确认没有该账号的在途生成，然后把「待删除」状态持久化；三只精灵的私人会话和该账号贡献的共同遭遇逐个幂等移除，**能量不倒退、其他旅人的原始会话不因删除而被改写**；最后移除账号和全部会话。删除前该账号已经消耗的当日全站额度必须并入不含身份的当日汇总，不能因删除账号而凭空返还、让反复注册绕过总预算。跨文件写入不是数据库事务：若中途崩溃，启动时须在开始监听之前继续未完成的清理；若运行中清理失败，待删除账号不能重新登录，其旧遭遇也不能进入其他人的模型上下文。单纯删账号文件或只补 UI 都不能满足这些不变量。比较过的第三条路径是把全体世界状态迁移到事务数据库，能直接提供原子提交，但会重写当前已运行的全部持久化与备份链路，当前数据量和单实例并未证明迁移收益大于风险。

备份是独立的删除边界：先确定并真实配置本地和 OSS 加密快照的保留期限，再建立一个不随旧快照回滚而丢失的删除记录；恢复旧快照必须重放此记录，才能重新开放服务。若做不到，页面只能如实说「已从在线世界移除，历史加密备份仍将在已披露期限内保存」，不能承诺旧数据已永久消失。保留期限、运营者可公开名称/联系渠道和衍生回复争议的人工申请路径仍待确定；它们不被这份技术设计视为已交付或从 AC-10/AC-11 移出。

验证要覆盖本人密码错误、匿名/跨账号请求、发消息与删除并发、三只精灵分别有记录、删除途中第二只精灵写盘失败后重启续做、删除前当日总额度不被返还、旧备份恢复后的删除记录重放，以及同名重新注册不会读到旧会话或旧共同遭遇。公网浏览器还需实际从已登录页面完成导出→确认删除→会话失效→同名新身份；任何失败场景都不能虚报完成。此设计不授权立即删除生产用户或旧备份。

## 失败、刷新与恢复矩阵

注册/登录弹窗的键盘合同：打开后焦点直接进入昵称输入框，Tab 与 Shift+Tab 只在弹窗内循环；Esc、关闭按钮或点击遮罩关闭后，焦点返回原触发控件。切换注册/登录模式重新聚焦昵称。昵称可在两种模式间保留，密码在模式切换或关闭弹窗时清空，避免失败注册的密码被误带到登录或留在下一次打开的弹窗中。保留现有视觉结构，不为这个局部行为重建一套对话框组件；真实浏览器键盘操作与触控操作都要通过。

| 场景 | 用户看到 | 服务端不变量 |
| --- | --- | --- |
| 注册重名、弱密码、超速 | 明确错误、可修改后重试 | 不创建半个账号 |
| 登录错误、会话过期 | 重新登录入口，不丢草稿 | 不泄露账号是否存在细节，不跨账号展示对话 |
| 模型超时、供应商失败 | 可重试状态 | 不保存伪回复，不扣成功能量/账号次数 |
| 发送中刷新或连接中断 | 刷新后从服务端读取最终对话；若没有则可重发 | 同一请求幂等或明确可安全重试，避免双扣 |
| 服务重启/版本更新 | 短暂离线后恢复 | 账号、会话、世界与对话从持久目录恢复；升级前有备份 |
| 超过限额或能量低 | 显示何时可再试/为什么不可唤醒 | 不产生模型账单 |
| 访客尝试读取他人会话/注入工具命令 | 拒绝或仅作普通对话文本 | 不执行宿主工具，不返回其他人的原始会话/密钥 |

## 黄金验收

1. 非开发机打开 HTTPS 入口 → 浏览星球 → 注册 → 与任意精灵连续问答两次 → 刷新、退出、登录 → 自己的两轮对话仍在。失败条件是只看到原型、注册后不能说话、二轮不连续或数据丢失。
2. 两个独立账号分别进入同一精灵 → A 留一个非私密线索 → B 询问 → 精灵能在共享上下文中处理该线索；B 不能通过 API/界面读取 A 的私人对话列表。失败条件是每账号一份精灵或会话串读。
