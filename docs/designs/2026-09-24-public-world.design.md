# 公开星球：使用、身份与部署设计

状态：Design Ready，按 `docs/plans/2026-09-24-public-launch.plan.md` 的 AC-01 至 AC-09 验收。目标是交付可分享的线上产品，而不是把 localhost 原型直接加一个代理。

## 新访客实际怎么用

一个从未听说 Bibo Planet 的人打开 `planet.bibo.bot`：首屏看到一颗星球、三只性格不同的精灵，理解「同一只精灵会遇见所有人，没有主人」。无需注册即可浏览精灵、能量和匿名化的星球近况。要说话时进入注册面板，取一个昵称、设密码，立即回到刚才选择的精灵；第一次发送能看到明确的等待状态和真实回复，继续追问可以延续自己的对话。退出后再登录，自己与各精灵的对话仍在。另一人注册后面对的是同一只精灵，它可引用此前的公开可共享经历，但不能打开前一人的原始对话记录。错误、能量不足、每日额度耗尽都有可理解的反馈和恢复路径。

## 真实候选与选择

| 路径 | 价值 | 代价/风险 | 结论 |
| --- | --- | --- | --- |
| 国内 ECS 上放完整 Node/Harness，Cloudflare 提供独立 HTTPS 入口 | 复用现有实例与 `@nextclaw/harness`，本机 DeepSeek 在国内可调用，持久磁盘现成 | 与现有服务同机；需隔离用户/目录、反代保护、备份、限流 | 采用，先小流量公开 |
| 全部放 Cloudflare Worker/D1，直接调模型 | 部署快、边缘扩缩容好 | Node Harness 与文件化精灵工作区难移植，会偏离 NextClaw 复用；存储模型需重写 | 不采用 |
| 境外节点运行完整 Harness，使用 `codex-sub` 订阅代理 | 模型能力强 | 个人订阅不适合作公开访客的生产 API；境外实例与持久存储待购置，且成本、可靠性未知 | 不采用；`codex-sub` 仅内部验证 |

`bibo.bot` 根域现在是另一产品站点，不覆盖它；使用 `planet.bibo.bot`。Cloudflare Worker 是独立 HTTPS 静态站与受控 API 代理，后端 Node 仅监听 loopback，由 ECS 现有 HTTPS Nginx 的独立路径代理，并要求仅 Worker 持有的随机认证头。Worker 与 ECS 间保持 HTTPS，不把模型密钥放在 Worker 或前端。Worker 自定义域名自动创建 DNS/证书；若该配置不可行，先用独立 `workers.dev` URL 验证但不把临时地址当最终品牌链接。Cloudflare 官方参考：https://developers.cloudflare.com/workers/configuration/routing/custom-domains/ 。

## 状态 owner 与运行边界

- `AuthStore` 拥有账号、密码哈希、会话 token 哈希、注册/登录/退出与每日账号额度。访客身份不再依赖可自填的 UUID cookie；cookie 为随机不可猜 token，`HttpOnly; Secure; SameSite=Lax`。所有修改原子落盘，进程单实例运行，服务升级前备份。
- `WorldStore` 继续拥有精灵能量、共享遭遇与各账号的私人对话。能量与对话只在模型成功后一起写入；同一精灵串行。公开世界接口只给必要的匿名化统计和有限事件摘录，不给其他用户的会话原文。
- `SpiritRuntime` 用 `@nextclaw/harness` 提供的模型注册/路由能力调用真实模型；传入精灵身份、该账号最近对话、共享遭遇与安全边界。**公开版不向模型提供文件、命令、网络工具**。现有完整 Agent `runTask` 在本地原型可用，但其工具拥有宿主能力，不能拿 `restrictToWorkspace` 冒充安全沙箱。精灵自主改造工作区与 mini-app 延后到真正有执行隔离之后，不能伪称已经开放。此取舍保留 NextClaw SDK 依赖与模型能力，但公开版暂不使用完整有工具的 Agent session，须对用户如实说明。
- API 服务拥有请求验证、来源检查、客户端/IP 速率限制和返回码。部署边界上，Node 进程使用非 root 专用账号、只读应用目录、单独可写数据目录、systemd 限权；Nginx 只暴露指定路径且校验内部认证头。公开可观察的敏感日志不记消息正文和密钥。

## 资源与滥用边界

每次消息最多 1500 字符，模型输出有 token 上限和超时；每账号每天有低额度，单 IP 对注册与登录限速，模型调用并发数有限，全站每日调用上限有限。前端显示真实能量，额外运营预算不伪装成精灵能量。任何模型失败不计为成功对话；供应商余额不足时全站明确告知，不切换模拟回复。初始阈值可按真实单轮 token 与费用再校准，必须保留管理端可调整而非永久硬编码虚假经济体系。

## 失败、刷新与恢复矩阵

| 场景 | 用户看到 | 服务端不变量 |
| --- | --- | --- |
| 注册重名、弱密码、超速 | 明确错误、可修改后重试 | 不创建半个账号 |
| 登录错误、会话过期 | 重新登录入口，不丢草稿 | 不泄露账号是否存在细节，不跨账号展示对话 |
| 模型超时、供应商失败 | 可重试状态 | 不保存伪回复，不扣成功能量/账号次数 |
| 发送中刷新或连接中断 | 刷新后从服务端读取最终对话；若没有则可重发 | 同一请求幂等或明确可安全重试，避免双扣 |
| 服务重启/版本更新 | 短暂离线后恢复 | 账号、会话、世界与对话从持久目录恢复；升级前有备份 |
| 超过限额或能量低 | 显示何时可再试/为什么不可唤醒 | 不产生模型账单 |
| 访客尝试读取他人会话/注入工具命令 | 拒绝或仅作普通对话文本 | 不执行宿主工具，不返回其他人的原始会话/密钥 |

## 黄金验收

1. 非开发机打开 HTTPS 入口 → 浏览星球 → 注册 → 与任意精灵连续问答两次 → 刷新、退出、登录 → 自己的两轮对话仍在。失败条件是只看到原型、注册后不能说话、二轮不连续或数据丢失。
2. 两个独立账号分别进入同一精灵 → A 留一个非私密线索 → B 询问 → 精灵能在共享上下文中处理该线索；B 不能通过 API/界面读取 A 的私人对话列表。失败条件是每账号一份精灵或会话串读。
3. 公网低额度、异常消息、恶意工具指令、直接访问 ECS 受保护路径、服务重启与备份恢复逐项检查。失败条件是无约束扣费、工具执行、凭据泄漏、绕开入口、不可恢复或错误被伪装为回复。

## 抽象与非目标审计

保留 `WorldStore` 单 owner、`SpiritRuntime` 模型入口和 `@nextclaw/harness` 公共能力；新增的 `AuthStore` 只服务明确的账号/会话/额度不变量。删除公开链路上的匿名身份 cookie 和完整有工具的 `runTask`；本地原型的数据不自动迁入新公开世界。延后精灵执行代码、mini-app、用户补能、复杂社交关系和邮件验证，不延后注册、真实 AI、共同记忆与基本安全。对外文案不能宣称精灵已经能自写代码或具有真正的自由意识。
