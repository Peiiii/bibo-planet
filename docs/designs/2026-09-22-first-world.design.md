# 第一颗星球：真实 MVP 设计

## 目标与体验

访客打开独立的星球页面，看到几只身份不同的精灵和各自剩余能量；选择一只精灵，留下一句话，收到真实模型的回复。另一位访客随后来到同一只精灵处，可以从它的共享记忆中感知此前发生过的事。页面刷新或服务重启后，能量、遭遇与对话仍在。能量耗尽时系统明确拒绝唤醒，不伪造回复。

当前交付是本机可运行、可由多个浏览器身份访问的 MVP 与 GitHub 源码，不是公开互联网部署。公开部署需要额外的执行隔离、滥用控制和身份机制。模型供应商须提供真实凭据；公开免费模型若拒绝第三方调用，系统明确失败，不切换成假回复。

## 路径比较

| 路径 | 收益 | 问题 | 结论 |
| --- | --- | --- | --- |
| 直接调用模型 API | 上手最快 | 精灵运行时与 NextClaw 分叉；需要重做 Agent 能力 | 放弃 |
| 直接开放 NextClaw 服务/API | SDK 现成 | 私人助手的权限、身份与产品语义不适合无主多人世界 | 放弃 |
| 新世界后端嵌入 `@nextclaw/harness` | Agent/会话复用，世界语义独立 | Harness 为 experimental；需限定本机与版本 | 采用 |

## 单一路径与状态 owner

服务器签发不可猜测的 HttpOnly 匿名访客 cookie → 世界后端接收消息 → 世界存储检查精灵能量并串行化同一精灵的唤醒 → 注入精灵近期共享遭遇 → Harness 以该精灵的 Agent ID 和该访客的稳定 session ID 运行 → 从完成消息读取实际 token usage（不可用时明确估算）→ 写入能量、访客对话和共享遭遇 → 返回回复与新状态。

世界存储是能量、访客对话和共享遭遇的唯一 owner；Harness 是 Agent 配置、工作目录和模型会话的唯一 owner。每只精灵对应一个 Harness Agent，且有自己的目录和身份说明。不同访客不共用原始 session，精灵通过共享遭遇接触跨访客历史。原始会话仅供当前访客在 UI 查看，不作为公共时间线。精灵无系统层面的 owner 字段。

## 资源与失败边界

- 初始每只精灵有明确的能量额度。每次运行前检查最低启动门槛；运行后按模型报告的 `totalTokens` 扣减。若报告不可用，按输入与输出文字长度估算，状态标注 `estimated`，不能伪称精确。
- 同一精灵的运行在单进程内串行，防止并发透支与共享记忆读写冲突。持久数据使用原子替换；其他精灵可独立运行。
- 运行失败不产生假回复，也不把未完成内容写成遭遇；错误反馈可重试。若模型报告到失败运行的消耗，后续需要扩展计量，本 MVP 明确不保证失败账单精确。
- 服务器默认只监听 `127.0.0.1`，禁止直接作为公网服务；Harness 工具限制在工作空间。进程级沙箱尚未实现，所以不能声称精灵绝对无法接触宿主资源。

## 黄金验收

1. 首次进入：启动服务 → 打开页面 → 看到至少三只不同的精灵及能量 → 任选一只发送消息 → 收到真实模型回复及扣减后的能量。模型不可用时显示真实错误，而不是演示文本。
2. 共同历史：访客 A 留下一个可辨认事实 → 使用新的访客身份与同一精灵对话 → 精灵可以基于共享遭遇回应；A、B 的原始对话列表不互相显示。刷新与重启后持续成立。
3. 资源边界：把能量调低至启动门槛以下 → 发送消息被明确拒绝，余额不变；管理员可通过本机 CLI 显式补充能量恢复对话，不开放匿名补能 API。

## 后续而非首版规则

精灵主动醒来、精灵间互动、访客补给、自由上传代码、精灵生成 mini-app 和公网托管仍属产品方向，但不是首次对话闭环的必要条件。尤其不能把未沙箱化的代码执行接入公开访问。首版前端自行实现，不复用 NextClaw 个人助手前端。
