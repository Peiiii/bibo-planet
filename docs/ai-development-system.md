# 跨项目 AI 开发体系：共享什么，不共享什么

本项目与 [NextClaw](https://github.com/Peiiii/nextclaw) 关联，但产品目标不同。NextClaw 服务于一个用户的长期搭档关系；Bibo Planet 是多人共享、无主人精灵的开放世界。直接复制 NextClaw 的 `AGENTS.md`、私人助手规则或前端，会把错误的使命和权限假设带进这里。

当前的可复用边界分两层：

1. **运行能力共享**：从 npm 使用版本固定的 `@nextclaw/harness`，由它拥有 Agent、会话和模型执行。本项目只拥有精灵世界的访客、共同遭遇和能量。两边通过公开包合同连接，不通过相邻目录深层导入。
2. **开发方法共享**：通用的头脑风暴、计划、编码、Git 等技能放在开发者全局的 `~/.agents/skills`，由多个项目共同发现；各仓库的 `AGENTS.md` 只放本产品的使命、安全边界与交付约定。本项目不复制 NextClaw 的仓库专属脚本或治理规则。

这是一种**共享基础、各自特化**的选择，不是说 NextClaw 当前项目内的所有 `development-*` Skill 已经被抽成独立公共包。它们含有 NextClaw 特有路径、命令和产品合同；现在机械搬运或 symlink 会制造无法在独立仓库运行的假共享。两个项目真实重复的流程变得稳定后，再把那部分抽成可版本化、能在第三个项目安装的独立技能包，并让两个仓库只保留特化层。首次候选应是「需求理解 → 设计与验收 → 实现 → 验证 → Review → 交付」，而非整包复制 NextClaw 项目规则。

本仓库的 `AGENTS.md` 是当前可执行的项目入口。它要求先读本产品设计，优先使用已经全局安装的通用 skills，验证真实链路与用户体验，并把新共性向共享层上提。新增公共层前，先在两个项目中找到重复的具体场景、输入/输出与失败案例；只有文档相似不算可复用证据。
