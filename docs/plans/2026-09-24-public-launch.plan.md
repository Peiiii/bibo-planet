## 用户目标与不可缩水的验收合同

用户要的不是本地演示，而是一个能直接交给新访客的线上产品：给出公开访问链接，新访客可注册、登录并与真实 AI 精灵持续对话；多人访问的是同一批没有主人的精灵，共同经历会影响它们。产品要足够有趣、独特、可用；交付前从产品吸引力、用户完整链路、上线可靠性三个角度各审查三轮，不能以测试通过替代真实体验。

## 方向与约束

- 独立项目、独立前端；不是 NextClaw 私人助手的皮肤。复用公开 `@nextclaw/harness` 的 Agent 运行能力，世界身份、记忆、能量和账号归本项目。
- 不写死主人、好感度、阵营或剧情；同一精灵可受所有访客影响，但访客对话原文不默认公开。
- 用户允许访问已登录的 GitHub、Cloudflare、阿里云和模型账户，允许创建所需资源与密钥；凭据不得写入仓库、输出或对话。预算谨慎，避免无上限的推理账单。
- 模型不限 DeepSeek，优先复用本机 NextClaw 已配置且实际可用的供应商。`codex-sub` 的 GPT 能力值得保留作内部开发/验证，但不能把个人订阅代理当成公开访客的产品 API；公网应使用适合第三方应用的正式 API。
- 部署位置服从模型链路：若依赖境外模型，使用境外节点；若使用国内 DeepSeek 等可达服务，可评估国内计算节点，但域名、可达性和合规性必须另证。
- 已有阿里云实例承载其他服务，不得覆盖或重启无关服务；先只读评估资源与部署隔离。Cloudflare 已登录，可评估 HTTPS 入口。

## 已核实的事实（2026-09-24）

- 仓库 `Peiiii/bibo-planet` 是独立 React/Vite + Node + `@nextclaw/harness` 本地原型，目前强制仅监听 `127.0.0.1`，没有注册/登录，不允许直接开放公网。
- 本机 NextClaw 配置中的 DeepSeek `deepseek-chat` 调用返回 HTTP 200 与真实内容；Agnes 测试也为 200。Dashscope、Xiaomi Mimo 当前为 401，MiniMax 当前为 429。需在目标部署区域重新验证连通和账单，不复制密钥到仓库。
- Cloudflare Wrangler 已登录；阿里云账户有一台运行中的杭州 ECS（2 vCPU、2 GB），属于其他现有服务。Cloud Assistant 在线，可先只读检查资源。不能推定它适合承载 Bibo。
- OpenAI 官方说明 ChatGPT 订阅与 API 分开计费；个人服务条款不允许把账号提供给他人。`codex-sub` 不能作为公开访客免费共享的默认模型。参考：https://help.openai.com/en/articles/9039756 与 https://openai.com/policies/row-terms-of-use/ 。
- 已用临时数据目录和真实 DeepSeek 从 HTTP 入口完成两个新账号注册、A 留下“蓝色风铃”、B 向同一只墨里询问并得到包含该线索的真实回复；A 的私人会话仅有 A 自己两条消息。另完成同账号连续两轮，第二轮能准确回应第一轮。真实调用报告了 token 用量。以上只证明本机链路，不证明公网体验。
- 公开实现改为 NextClaw Harness 的无工具模型能力；三只精灵的身份与世界记忆仍由 Bibo 持有。账号密码 scrypt 哈希、随机会话、每日额度、注册/登录节流、请求来源与边缘认证都已写入代码；仍需线上压力、安全和恢复检查。
- `planet.bibo.bot` 使用独立 Cloudflare Worker 静态资源与 API 代理的配置已完成 dry-run；部署目标还未启用。

## 待决策与执行序列

1. 只读核查可用计算节点、资源、网络与 Cloudflare 域名；比较境外服务器、国内 ECS + 国内模型、Cloudflare 原生运行的稳定性和成本。先选可持续的部署路径。
