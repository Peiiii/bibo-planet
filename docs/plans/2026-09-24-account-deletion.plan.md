# 旅人账号与交互数据删除 Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 让旅人经再次验证后移除活动世界中的本人账号、私人会话及本人贡献的共同遭遇，且模型生成、进程崩溃和旧备份恢复都不能使这些原文重新出现。

**Architecture:** `AuthStore` 是账号、会话、删除中标记与每日额度的 owner；`WorldStore` 是三只精灵状态及模型可读共同记忆的 owner。一个实际跨文件事务协调者按“冻结身份 → 记录不可回滚删除标记 → 幂等清理精灵 → 删除账号”推进，并在服务监听前恢复中断的删除。旧备份恢复须先读取独立于旧快照的删除记录、重放清理，才允许对外提供服务。

**Tech Stack:** TypeScript、Node.js、现有 JSON 原子写盘、`node:test`；暂不迁移数据库。生产加密备份与私有 OSS 的保留/删除策略另设真实配置和验收。

---

## 方案与边界

已有[公网设计](../designs/2026-09-24-public-world.design.md#账号删除的可执行边界待实现不等于全部数据即时消失)比较三条路径，本计划执行“删除本人原文与其贡献的共同遭遇”。不把自由文本仅去身份后留在共享记忆；不为首版重写全部状态为数据库。账号删除不可能自动收回其他旅人此前已经收到的衍生回复，也不能使已生成的历史加密备份瞬间消失。页面必须说明这些残留边界，不得用“永久全部删除”文案。

官方依据及适用性待专业核定：[拟人化互动服务办法第十六条](https://www.cac.gov.cn/2026-04/10/c_1777558395078289.htm)要求交互数据复制、删除选项；[个人信息保护法第四十七条](https://www.npc.gov.cn/WZWSREL25wYy9jMi9jMzA4MzQvMjAyMTA4L3QyMDIxMDgyMF8zMTMwODguaHRtbD9yZWY9aW1i)列出删除请求与技术上难以实现时的限制处理。Bibo 是否落入特定服务定义及运营手续仍是 AC-11，不能靠功能代码自证。

## Task 1：失败测试先锁定删除合同

**Files:** `test/auth-store.test.ts`、`test/world-store.test.ts`、`test/server.test.ts`。

1. 在隔离数据目录造两个账号、三只精灵均有本人和他人记录；测试删除本人后自己的账号/会话/共同遭遇均不可读，另一人的私人原文与能量保持不变。
2. 测试匿名、错误密码、跨账号伪造 ID 和与在途模型调用并发的拒绝路径；必须先失败再实现。
3. 在第二只精灵持久化处注入一次失败，重新初始化协调者后续做；任何阶段不能使被删旅人的旧文字回到模型共享记忆。
4. 测试删除前消耗的世界每日尝试额度不被返还，成功重放不会重复累计。
5. 用一个删除前的旧快照覆盖账号/精灵文件、保留独立删除记录，启动前重放后不得复活本人数据。

## Task 2：账号冻结与世界预算

**Files:** `src/server/auth-store.ts`、`test/auth-store.test.ts`。

1. 账号记录新增可选 `deleting` 标记；旧账号文件继续兼容。再次验证密码且没有本人在途调用时，在现有串行队列中持久标记删除，随后所有本人会话、登录和新模型调用均拒绝。
2. 现有成功与尝试额度在最终移除账号前写入不含身份的按日汇总；`withMessagePermit` 的世界上限计算包括该汇总，不因同名重新注册而返还额度。
3. 完成删除时清理全部会话 token 和账号；若账号已移除，重复完成应为幂等成功，不重复累计额度。

## Task 3：共同世界清理与跨文件续做

**Files:** `src/server/world-store.ts`、新增 `src/server/account-deletion.ts`、`src/server/main.ts`、相关测试。

1. 删除协调者先持久记录只含账号 ID/时间的墓碑；它存放在旧账号/精灵快照恢复时不会被覆盖的位置。墓碑丢失时不得直接开放旧快照；这需要独立离机备份合同，不能仅靠同机文件。
2. `WorldStore` 在墓碑存在或账号 `deleting` 时立即屏蔽其遭遇进入 `recentEncounters` 与 `relevantOlderEncounters`；随后在每只精灵自己的写队列中幂等移除 `conversations[accountId]` 和 `encounters` 中该 ID 的条目，能量不回补。
3. 进程启动加载墓碑和账号状态后、启动模型与监听端口前，重放全部未完成删除；清理失败则拒绝服务启动，不能带着可泄露旧记忆继续运行。
4. 明确生产恢复合同：把旧备份恢复到隔离目录时必须同时携带最新墓碑，完成重放后才切换为活动数据。没有独立离机墓碑与实际恢复验证，不发布对外删除入口。

## Task 4：账号接口与页面

**Files:** `src/server/server.ts`、`src/client/app.tsx`、`src/shared/world.ts`、`test/server.test.ts`、用户文档。

1. 新增仅当前会话可调用的删除接口，不接受客户端提供的账号 ID；请求体必须包含再次输入的密码和明确确认。失败不可返回“已删除”。
2. 在“导出我的数据”附近提供「账号与数据」入口：先说明活动数据范围、共享记忆移除、旧加密备份期限以及衍生回复边界，再提交删除。成功后前端清空本人会话与登录状态；旧 token 实际返回 401。
3. 桌面与 320px 手机真实浏览器按“导出 → 确认删除 → 会话失效 → 同名新身份无旧数据”验收；无法做真实浏览器检查时保持 UI 验收开放。

截至 2026-09-24 16:52，北京时间：API 与默认关闭的页面已在本地实现；30/30 测试、TypeScript、lint、格式、构建通过。隔离本地浏览器完成注册、桌面弹窗与 320×700 窄屏布局检查；点击导出确认后浏览器控制挂起，尚未完成浏览器下载和删除成功 UI 验收。不能把 API 测试或布局截图当作完整 Task 4 通过。

## Task 5：发布门槛

1. 用户确认备份保留期、公开运营者与联系渠道；运营方核定首发市场及适用要求。将本地与 OSS 生命周期真实配置为披露的到期规则，覆盖每日与早期手工/明文副本，验证范围不会误删恢复必需墓碑；OSS 按日执行可能延迟，不能承诺精确的硬上限。
2. 在 Bibo 专用备份后，先以隔离恢复副本演练旧快照 + 最新墓碑防回流，观察中途崩溃续做；运行 TypeScript、完整测试、lint、构建、Worker dry-run 与真实公网账户链路。
3. 只对专门创建的测试账号进行公网删除验收，**不删除现有真实旅人或旧备份**。AC-10/AC-11 仍须分别核对运营、法规和权利处理范围，不因接口存在而自动通过。
